## 不降低的正确性门槛

- 2 对 2、180 秒、单层既有地图拓扑；覆盖率决定胜负，出生区不计分且受保护。
- 墙体同时约束人物、冲刺、弹道和涂色；有限液量/再生、花苞规则、4 秒复活和机器人战斗继续成立。
- 真正的肩后透视、相机相对移动、有限仰俯、掩体避让；准星目标与实际枪口弹道一致，不能借相机越墙射击。
- 权威覆盖数组、上传纹理和计分逐格一致。角色、地面、液滴及 HUD 可以更换显示色，不能更改队伍归属编码。
- 暂停/失焦/结算/退出释放输入；重开彻底清理实例、池和历史；普通关闭窗口必须由产品路径正常释放音频、场景与指针。
- 保存仍只写本模块，未知未来格式不覆盖；宿主、旧游戏、第二入口、独立提取均不回归。

## 冻结后的执行顺序

1. **冻结确认**：收集美术、HUD、运行时所有者完成消息；记录最终源码/资源集合的全新 SHA-256 清单。旧 66 文件清单只保留作历史，不用来证明本轮测试。
2. **便宜前置**：检查脚本/导入、现行美术校验、音频清单/版权、模块资源引用；`ui/subset_font.py --check` 验证冻结后模块全部 GDScript 的可打印代码点及 ASCII 运行时数字均在本地 SC Bold 字体子集中（已接入 aggregate，不把当前旧子集当通过）。新 HUD 的正式状态 API 稳定后检查生命、液量、时间、覆盖率、两名队员、冷却、暂停与结算数据。
3. **完整自动回归**：运行 `tools/test_all.sh`，不使用 quick 模式；包括两游戏及宿主、12 组双实例完整随机比赛、20 次生命周期、未来存档、648 相机姿态、逐格纹理/计分、液体池压力、4 种真实关闭通知以及真正提取工程的重复规则/相机/关闭检查。逐阶段保存日志，并拒绝零退出码但包含引擎错误或泄漏警告的结果。
4. **新 HUD/视觉专项**：按 1280×720、960×540、1280×800、1024×768 检查可见区域、字形/数字、2v2 指示、生命/液量/技能反馈、遮挡准星、暂停/结算按钮和返回路径。队色须在人物、喷射、地面、队标和 HUD 一致；仅环境植物使用绿色。通过真实运行画面检查，不用源码颜色常量代替观看。
5. **真实原生运行**（root 主持）：鼠标捕获、俯仰/移动/墙边瞄准、连喷与补液、冲刺/花苞/受击/复活、失焦/暂停/恢复、自然 180 秒结束、真实点击重开/回岛，以及音频活跃时 Alt-F4。近景必须能看到肢体/武器/前方地面，不被新储液罐或环境遮住。
6. **证据收口**：重算冻结清单，确认测试期间实现未变；只把实际完成的项目写为通过。新实际帧/动态片段与概念图明确分开。视觉是否满足用户的新独立风格仍须以用户评价为准，技术通过不等于整体接受。
