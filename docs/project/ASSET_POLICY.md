# 素材与仓库策略

## 当前版本只保留一份运行成品

运行需要的 GLB/WAV/字体与许可证直接入库，克隆后无需 Blender 即可运行 Godot。当前海岛成品以 `godot/resources/` 为规范位置；九项完全相同的作者目录导出副本不再入 Git。本地作者导出路径保留在 `docs/active_asset_manifest.json`，用于显式重建后同步，不是运行前提。

保留当前实际依赖的最新可编辑 `.blend`、Python 生成器、音频谱面与来源记录。特别是 `art/v3/{landscape,plants,animals}.blend` 仍被当前环境和骨骼生成器直接读取，不因版本号旧而删除。

## 不再跟踪的内容

- 已被替代的旧汇总模型、旧未绑骨导出、旧海鸥与被否定的写实植物试验二进制。
- 可重新生成的预览 PNG/GIF/MP4、音频试听版、作者目录的重复导出。
- `.godot/`、缓存、逐帧渲染、编辑器临时备份、工程压缩包、日志、引擎安装包。

旧版本和原验收预览可从 Git 历史恢复，不把所有历史二进制永远保留在最新工作树。删除不会重写 Git 历史，因此当前树/源码包减少不等于旧仓库历史体积已缩小。不得为此擅自 force push 或清除历史。

## 同步与校验

`docs/active_asset_manifest.json` 显式限定可同步路径，`docs/resource_manifest.json` 锁定已提交成品的字节数与 SHA-256。禁止通配旧目录覆盖当前模型。作者导出缺失时必须验证运行成品与锁记录一致，不能通过重新计算锁掩盖损坏；新导出只在显式同步时采用。

纯检查使用 `python3 tools/sync_resources.py --check`；生成新的模型/音乐后，检查源文件并显式同步。Blender 重导出不保证跨版本字节一致，成品哈希是已提交版本的身份，不代表跨工具版本生成必然相同。

独立小游戏素材、当前编辑源、来源及许可证保留在各自模块内；模块不依赖海岛或其他游戏。为节省大小不能跨模块共享字体/存档/美术而破坏可抽离性。完整清理路径和验证见 `docs/maintenance/`。
