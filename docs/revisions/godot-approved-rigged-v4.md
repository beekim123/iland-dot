# 已验收模型与真实骨骼接入 Godot · v4

用户明确验收新模型并要求加入 Godot 后执行。未改变已认可的模型造型、原始配色或 Blender 源文件。

## 资源与回退
- 静态环境：`art/v3/environment_v3.glb`，包含已组装的新地形与植物，不包含重复的静态动物。
- 动物：`art/rigged/{turtle,crab,seagull,fish}/*_rigged.glb`。
- `docs/active_asset_manifest.json` 是当前唯一同步来源；`tools/sync_resources.py` 不再扫描旧 `art/export/`，避免旧模型意外覆盖新版。
- 同步后的 SHA-256 在 `docs/resource_manifest.json`。
- 接入前完整运行工程、脚本与工具快照：`backups/godot_v2_before_rigged_v4.tar.gz`（不含可重建的 Godot 导入缓存）。建议先解压到新目录检查，不直接覆盖当前交付。
- 既有 v1/v2 已交付 GIF/MP4 未覆盖。

## 骨骼驱动
运行场景含19个实际 Skeleton3D：海龟、螃蟹、海鸥各1个，以及16条鱼。骨骼数分别15、26、17、11；蒙皮和骨骼通道由独立审计确认。

`bone_actor.gd` 驱动导入的 AnimationPlayer，使用实际骨骼动作：
- Turtle_Swim_Loop_4s
- Crab_Scuttle（Godot 导入后名称，原GLB为Crab_Scuttle_Loop）
- Fly / Glide
- Swim

Godot 导入片段长度约4.041667秒；直接导入姿态检验证明0与末端闭合。为保持制作约定的4秒周期，采样为 `fposmod(t,4)/4 * imported_length`，随后立即更新骨骼。未采用错误的1/24秒偏移。旧版 MeshInstance 枢轴、拉伸翅膀、手动收脚和鳍片摆动全部移除；世界路线仍由程序控制，但局部变形由真实骨骼/蒙皮完成。

海龟和鱼进入新地形前景水域；螃蟹使用新沙滩平整区，海鸥沿空中路径飞行。陆地模型比例沿用已验收组装尺度。两群鱼均保留已认可的小丑鱼配色，不再给其中一群强制染蓝。

## 海水与材质
海平面采用新地形约定−0.10米；波浪、浪花、深浅分区由新的256点海岸契约驱动，不沿用旧椭圆。隐藏源场景的旧海面/泡沫，保留新地形、植物、装饰。

实际图形检查发现地形先纯白、再偏深绿/橙色。问题是导入的COLOR_0未启用，以及Compatibility未进行线性顶点色到sRGB编码转换，不是源配色问题。修复只创建运行时地形网格副本：保留位置/法线/拓扑，颜色按 `linear_to_srgb` 编码一次；明确白色albedo，启用顶点色。源GLB与其他正确导入的材质均不改动。独立诊断及官方依据见 `docs/godot-rigging-qa.md`。

## 实际视口与导出
`tools/run.sh --shots` 从真实图形窗口输出五张 v4 PNG，包括总览、海岸、无HUD总览、游泳近景、飞行近景。
`tools/run.sh --gif` 采集120张真实视口，12fps固定模拟时间，共10秒：
- 0–2秒总览；
- 2–6秒海龟、鱼群及沙滩近景；
- 6–8秒跟随海鸥的骨骼近景；
- 8–10秒返回总览。

`tools/encode_gif.sh` 输出新的 `sunny_shell_island_motion_v4.gif`；`tools/encode_video.sh` 输出同批画面的 `sunny_shell_island_motion_v4.mp4`，使用原有原创音乐和海浪，不添加新声音。GIF无声。源帧在 `art/previews/runtime/gif_frames_v4/`。镜头近景有意不包含全部场景对象，不应将镜头外的右侧鱼群或地形当作模型缺失。
