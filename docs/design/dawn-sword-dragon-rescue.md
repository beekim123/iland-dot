# 《晨曦之剑：龙塔救援》设计草案 v0.1

> 状态：用户于 2026-10-28 确认此设计方向，进入待开发队列。尚未实现；名称、人名与数值为设计目标，不是完成成果。

## 1. 一句话定位

一款**纯 2D 手绘横版动作冒险**：年轻勇者带着一柄旧剑，穿过森林、古桥与燃烧城堡，登上恶龙占据的高塔，救出公主，击败恶龙，和她一起迎接王国的黎明。

不反转“勇者救公主打恶龙”，不加入“公主才是反派”或“恶龙其实无辜”等颠覆。核心情绪是出发的勇气、旅途的险阻、终于抵达的紧张，以及真诚明亮的团圆。

建议规模：单人、5 章、首次通关目标 60–90 分钟（不含大量重试）；约 20 个主要关卡段落、4 个区域头目及最终恶龙。该时长是待试玩验证的目标，不是当前已有内容或工期承诺。线性主路线配少量可选岔路，不做开放世界。

## 2. 三个必须成立的支柱

1. **拿起剑就好玩**：移动、跳跃、攻击、闪避四项基本行为立即可用；少量动作形成完整节奏，不靠刷装备填充时间。
2. **每一章像翻进一本新的冒险绘本**：独立原创人物与场景语言，轮廓清楚、笔触可见、色彩随旅程变化，不复用前作角色与贴图换色。
3. **确实完成一次营救**：从公主被掳到救出、击龙、返乡都有可玩内容与结局，不在第一关或 Boss 出现时戛然而止。

## 3. 世界、人物与完整故事

### 主要人物

- **勇者莱恩（暂名）**：不是天降无敌的战神，而是肯挺身而出的青年护卫。短斗篷、轻便皮甲、旧钢剑；轮廓俊朗但不写实厚重。成长表现为出招更从容、剑获得晨光铭文，不做不断更换整套装备。
- **公主艾琳（暂名）**：王国的公主，勇敢、温柔，有实际判断力；被恶龙掳走仍设法留下求救标记，并保护同囚者。她需要勇者营救，但不是毫无行动的奖品。被救出后协助开启古代防护机关，不成为长程脆弱护送对象，也不抢走勇者击龙的主角位置。
- **赤焰恶龙格拉姆（暂名）**：有明确的掠夺欲与威胁性，袭击王都、掳走公主，占据山巅龙塔。体型、翼展、火焰和破坏场景共同建立压迫感；是需要被打败的真正恶龙。
- **老守桥人**：短暂出现的引路者，负责交代古城通路与晨光铭文。支线人物少而鲜明，不设置大量对话树。

### 起承转合

- **起｜被火焰划开的庆典**：可操作的村镇序章中学习行走和跳跃；恶龙袭来，公主为掩护平民被掳。玩家穿过受损街道，第一次用剑保护居民，主动踏上营救路。
- **承｜沿着公主留下的线索前进**：森林中的丝带、古桥上的王室符号确认方向；勇者救助守桥人，获得通往山城的路线，逐渐看见龙火造成的后果。
- **转｜登塔前最后的考验**：赤焰城关中，勇者击败龙的守门骑士，取得晨光铭文。龙毁掉来路，前方只剩向上的路。这里是紧张升级，不是故事反转。
- **合｜先救人，再决战，再返乡**：勇者抵达囚室，亲手破开封印救出公主；两人完成一段短逃离与机关合作。公主进入安全的防护厅，勇者迎战恶龙。击败恶龙后两人走出高塔，返乡短可玩尾声、完整结局画面及制作名单收束。

叙事采用短对白、场景演出和可操作过场；单次强制停手通常不超过约 30 秒，全部可跳过并可在暂停菜单回看关键目标。

## 4. 核心操作与战斗

### 默认键位建议（开工后验证并支持重映射）

| 动作 | 键盘 | 手柄 |
|---|---|---|
| 左右移动 | A / D 或左右方向键 | 左摇杆 / 十字键 |
| 跳跃（长按略增高度） | Space | A / 下方键 |
| 轻攻击 | J | X / 左侧键 |
| 闪避 | K | B / 右侧键 |
| 举盾 | L | LB |
| 晨光斩（第 4 章获得） | U | Y / 上方键 |
| 互动 | E | RB |
| 暂停 | Esc | Menu |

动作以键位逻辑名称提示，不将 Xbox 字母写死。无需鼠标瞄准。

### 战斗节奏

- **剑击**：地面三段连击，空中一段斩击。前两段轻快，第三段伤害和击退较强但收招更长。敌人受击闪白、方向击退、命中音效和轻微停顿提供反馈；不是浮空无限连。
- **闪避**：短距离翻滚，起始有短暂无敌窗口，结束有明确恢复段，不能无脑连续穿过全部攻击。无耐力条，避免早期同时学习过多资源。
- **盾防**：挡正面普通攻击但被推退，连续重击会击破防御并短暂硬直；火焰持续地带与标红重击不可挡。精确举盾可打断特定普通敌人，但不是通关必需。
- **晨光斩**：第 4 章获得的固定强化，击破暗焰封锁、打断指定龙息前摇；使用充能由近战命中累积，Boss 战提供确定性充能机会。绝不让进度依赖随机掉落。
- **恢复**：初始三次治疗储量，短读条、有受击风险，篝火补满。仅一套主武器，不做复杂武器树、掉装稀有度或材料合成。

设计理由：剑、盾与翻滚符合传统勇者形象；稳定动作集合降低手绘动画量，同时能让普通敌人的组合产生变化。精准操作有奖励，但普通模式允许玩家用观察、盾防与治疗过关。

### 移动与关卡互动

跑动、可变高度跳跃、短距离攀边、下落平台、梯子与翻滚。采用起跳宽限和落地前输入缓冲，目标是“手绘也灵敏”。不加入二段跳、钩索、游泳等需要大量专属关卡的系统。

平台挑战以坍塌木桥、摆锤、升降台、喷焰间歇为主；危险物先展示再组合。致命落坑扣一小段生命并放回最近安全地面，不强迫整关重跑。

## 5. 五章内容与难度曲线

| 章节 / 目标时长 | 区域与可玩目标 | 敌人组合 | 头目与教学回收 |
|---|---|---|---|
| 1. 离乡之剑 / 10–15 分钟 | 庆典镇→林间路→伐木营；完成出发、救人、寻找公主线索 | 持棒劫匪、野狼 | 巨斧匪首：大幅前摇、横扫与跳劈，教观察后出手 |
| 2. 风雨古桥 / 12–16 分钟 | 森林遗迹→断桥→钟楼；开闸建立捷径 | 盾兵、弓手；与旧敌少量混编 | 铁甲桥卫：正面格挡、背后破绽、落锤震波，教走位而非硬砍 |
| 3. 暮色山道 / 12–18 分钟 | 峡谷→矿道→山城外墙；火焰威胁首次贯穿场景 | 洞穴蝠、火蜥蜴、投石兵 | 岩壳巨蜥：冲锋撞墙露弱点，组合跳跃与闪避 |
| 4. 赤焰城关 / 14–20 分钟 | 城门→兵营→铭文圣堂；取得晨光斩、打开登塔门 | 重甲卫、火术士；慎用远近夹击 | 灰烬骑士：两阶段剑盾决斗，将前面学会的节奏集中检验 |
| 5. 龙塔黎明 / 12–21 分钟 | 塔楼→囚室营救→短逃离→龙巢→返乡尾声 | 精选既有敌人，避免最终章强塞新规则 | 赤焰恶龙：完整三阶段，结束后真正展示营救结果 |

总计建议 9 种普通敌人（持棒劫匪、野狼、盾兵、弓手、洞穴蝠、火蜥蜴、投石兵、重甲卫、火术士），4 个区域头目和 1 个最终 Boss。每章约 4 个主要段落，平均每 3–5 分钟出现安全节点或明显段落目标；最多同时围攻的敌人以 3–4 名为设计基线。

每章设置 1 条可选短岔路，奖励一幅王国记忆插画或生命碎片。不把找齐收藏品作为击龙条件；基础路线可独立通关。生命碎片采用固定位置，无随机刷取。

## 6. 最终恶龙战：高潮不能只是大血条

**竞技场**：龙塔顶层横向大平台，左右两端有明显掩体；镜头拉远但保留勇者可辨识尺寸。公主在场外防护厅，故事上安全，不挂一条容易失败的护送血量。

1. **第一阶段｜龙爪试探**：龙停在平台边缘，爪击、咬击与低位横扫。勇者躲开后攻击头部或前爪；前摇用姿态、音效与地面预警共同呈现。
2. **第二阶段｜烈焰封场**：恶龙升空，按明确路径喷火；玩家利用掩体与安全空隙移动。落地后晨光斩打断蓄力龙息，暴露胸前弱点。公主开启防护机关提示安全区，但无需玩家同时操控她。
3. **第三阶段｜最后一剑**：场景破损、动作组合加快而非取消前摇；恶龙猛扑后被塔柱短暂牵制。玩家在一次完整反击窗口内自行完成终结，不用不可预知的 QTE。

三阶段目标总时长约 4–6 分钟，失败整场重试，重试前跳过已见剧情。难度由招式组合提升，不用强制命中、离屏瞬杀、无提示地板崩塌制造压迫。

## 7. 存档、失败、继续与重复游玩

- 主菜单：继续冒险、新的冒险、章节回顾（通关后解锁）、设置、退出；重开覆盖存档需明确确认。
- 单一冒险槽为首版基线；存档写入已解锁章节、当前篝火、固定升级、收藏品、难度、设置与是否通关。
- 篝火和章节结算自动保存；退出时提示最近保存位置。设置即时保存；不保存 Boss 中途血量，避免复杂状态恢复。
- 普通战斗死亡返回最近篝火，恢复生命与药；已获得的固定升级/收藏品保留，不掉经验、不捡尸。普通敌人重置，已开启捷径保持开启。
- 每个 Boss 门外放篝火。重试按钮应迅速回到可控状态，不重复长对话；复活时清除飞行弹体、敌方仇恨、旧镜头锁定和临时攻击状态。
- 设“冒险”与“故事”两档；故事模式降低敌方伤害并增加治疗，不删招式与剧情，可随时切换。不设死亡次数结局惩罚。
- 通关后可回顾章节、补收集和再战 Boss；不强加多周目刷等级。结局明确完成营救，不用“敬请期待”代替内容。

## 8. 纯手绘视觉定义

### 建议方向：明亮英雄绘本 + 深色龙火阴影

使用有粗细变化的墨线、可见纸面肌理、平涂色块上的水彩/彩铅阴影。人物约 4–5 头身，姿态有力度，表情清晰；不做大头软糖玩具、不做像素风、不做 3D 渲染加描边的伪手绘。

角色以逐帧手绘动作为主，背景采用分层手绘。允许工具辅助排版、切帧、色彩校正与拼接；不得用整张立绘的平移缩放冒充跑步、挥剑和受击。若使用生成工具辅助绘画，仍需先定角色设定、再保证动作一致性，不能把自动生成结果直接当作通过验收。

- 勇者：象牙白与旧蓝，少量金色点缀；剑刃亮而不泛滥发光。
- 公主：暖白、深红披肩，与勇者色彩形成温暖搭配；旅行逃离时姿态自然。
- 恶龙：深朱红鳞片、焦黑翼膜、金黄裂隙火光；剪影一眼就认出头角、长颈与巨翼。
- 区域色脚本：晨间金绿→雨青石灰→紫暮赭石→暗红焦黑→黎明淡金。
- 可行走平台的前缘具有一致深线；背景降低对比与饱和度。装饰火焰与会伤人的火焰明确区分，不能只凭颜色辨识危险。
- 世界保持横版正侧视，背景允许绘画透视；场景层级至少分远景、中景、玩法层、近景，近景不得遮蔽敌人前摇。

### UI 与声音

HUD 只保留生命、治疗次数和后期晨光充能；手绘边框，文字使用清楚易读的中文字体而非难认的拟手写字。Boss 血条只在交战时出现，任务目标简短，例如“穿过古桥，追上龙的踪迹”。地图采用章节点位路线图，不做大尺寸迷宫地图。

提供音量、窗口/全屏、键位重映射、震屏开关、闪光强度设置与字幕。配乐以弦乐、木管和行进鼓点为主；营地安静、Boss 强烈、结局恢复序章主题。命中、格挡、重击预警和龙息的音色互不混淆。

## 9. 美术与动画产线（本轮只定义，不生成）

1. **文字风格锁定**：确认人物比例、线条、明暗、血腥程度与目标屏幕可读性。
2. **设定稿批准**：勇者/公主/恶龙三视或关键视角、统一身高尺、武器与配色、五章色脚本；先批准再批量制作。
3. **动作表与碰撞约定**：每个动作注明起手/有效/恢复阶段、朝向、帧数、枢轴、脚底基线、占用范围、命中事件；碰撞体独立于画面轮廓，不随每帧轮廓抖动。
4. **试产完整动作组**：先验收勇者跑、跳、落地、三连击、举盾、闪避、受击、死亡；同时验证一名敌人与一套地形的实机可读性。这是制作流程检查，不是用户最终只收一关的边界。
5. **分章生产与装配**：资产登记表含唯一 ID、来源、作者/工具、参考版本、导出设置及可用状态。源文件、透明 PNG 帧/图集、动画事件表、场景配置分开保存。
6. **动作 QA**：检查手脚数量、剑盾一致性、重心、接地、循环衔接、挥剑弧线、受击反馈；左右翻转时检查纹章、惯用手与特效位置。不合格帧修正而非仅靠加速掩盖。

勇者基础动作约 18–22 项，公主约 6–8 项，普通敌人各约 5–7 项，区域头目各约 8–12 项，恶龙另列飞行/喷火/落地/三阶段动作。逐帧数量取决于动作节奏，不能提前用一个固定帧数覆盖所有动作。画面可采用约 12–18 张关键/过渡画帧每秒的观感，游戏逻辑与输入保持独立更新；这只是风格与预算基线，需通过动作试产确定。

全新美术包必须拥有自己的角色、敌人、背景、UI 装饰、特效与色板，不能把历史项目素材换色后当作新游戏。制作前建立精确资产清单与估时，优先保证关键动作完整，再增加背景装饰密度。

## 10. Godot 工程与独立模块边界

以下为架构建议，不假设已核对 iland-dot 仓库，也不指定未经确认的引擎版本。

- 游戏内容根目录独立，例如 `games/dawn_rescue/`：`scenes/`、`actors/`、`levels/`、`art/`、`audio/`、`ui/`、`data/`、`tests/`；全新资源路径和命名空间，不修改其他游戏美术。
- 可抽离的通用模块：输入动作映射、暂停与设置、存档服务、音量总线、场景切换、伤害接口、命中盒/受击盒、检查点服务。共用接口，不共用本作角色设定与关卡脚本。
- 本作专属模块：剑盾动作状态机、晨光斩、恶龙阶段控制、公主营救演出、五章进度、绘本 UI 皮肤。
- 角色与敌人由数据资源配置生命、速度、招式参数；关卡只调用公开接口/信号，不依赖具体全局节点路径。
- 资产路径、InputMap、碰撞层、存档键均命名隔离。存档包含游戏 ID 与版本，错误/旧版数据有安全回退，不覆盖其他游戏进度。
- 如果接入 iland-dot 入口，只通过明确的启动/退出/进度接口连接；本作应能在独立 Godot 工程壳运行。抽离验收是复制本作与声明依赖后可以启动、通关并存档，不仅仅是“目录看起来独立”。

理由：复用稳定底层能力节省开发成本，但作品辨识度与玩法规则必须留在自己的模块内。先验证仓库实际结构，再选择最小必要接入方式，不能凭本草案直接重构现有工程。

## 11. 首个完整可玩交付边界

**交付应是一部短而完整的游戏，而不是把教程演示称为完整版。**

必须包含：

- 五章全部主线可玩；开场、公主营救、恶龙决战、返乡结局闭环。
- 勇者完整基础动作和晨光斩；普通敌人组合、4 个区域头目、1 个完整恶龙 Boss。
- 每章正式手绘场景与角色动作，主要玩法对象无临时占位图；独立 UI 视觉及完整反馈音效。
- 主菜单、暂停、设置、检查点、退出再继续、死亡重试、通关状态、章节回顾。

首版不做：开放世界、多人联机、分支结局、角色捏脸、背包负重、随机掉装、程序地牢、复杂制作系统、配音全覆盖、冗长护送、多武器成长树。

### 验收不是只看截图

1. 新存档从开始到结局连续通关一次；测试正常路线与每章可选岔路。
2. 每章保存退出再恢复；Boss 门前恢复；通关后恢复；损坏存档安全提示。
3. 死亡、落坑、暂停、窗口失焦、切换输入设备后不锁死状态；演出跳过不漏开门或奖励。
4. Boss 三阶段全部可触发和重试，无镜头/场景残留；公主营救标记只执行一次。
5. 检查完整动画列表与素材源文件；不以跑动贴图漂移代替动作。
6. 测量首次试玩时长与失败热点，再调整至 60–90 分钟目标；不靠提高血量凑时长。
7. 目标机器与发布平台确认后制定并测量帧率、内存与加载预算；未测量前不宣称性能达标。

### 分阶段推进但不缩减最终承诺

方向与资产表确认 → 完整战斗/动画试产 → 五章灰盒贯通 → 正式美术逐章替换 → 完整流程与存档测试 → 全量交付。早期内部验证可以小，但对用户的首个正式交付仍应包含上述完整体验；若资源不足，应先协商缩减范围，不能偷偷交成单关小样。
