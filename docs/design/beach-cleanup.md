# 第五款 · 拾光海滩 / Beach Cleanup

**模块：`beach_cleanup`｜状态：设计完成、已排队，尚未开发。** 《鹈鹕急送》完整交付后自动开工；不与前一款并行制作。数值是初始调参目标，不是完成或实测声明。见[开发队列](../project/DEVELOPMENT-QUEUE.md)。

## 体验与独立视觉

独立斜俯视 3D **沙雕微缩玩具风**：哑光沙感体块、小型清洁车、清楚的夹钳和可读分区。既不继承小鱼水彩，也不套用旧糖果视觉。核心是从杂乱到洁净的可见改变，以及满载时选返站路线的轻策略，不是垃圾分类考试。

## 操作与路线决策

建议 WASD 驾驶，持续按住左键使车身前方扇形夹钳连续夹取，松开停止；定稿须结合实机可达性测试。垃圾进入夹取范围与夹钳动作一致，不能隔墙吸取或拾取车后物品。

- 车容量 12 格，普通垃圾占 1 格、大件占 3 格；容量不足时清楚提示，不吞掉物品或扣分。
- 满车到卸货站清空，无罚分；可提前返站。大件可挡住捷径，先清理它换取更短往返路线。
- 没有硬失败、强制倒计时、耐力、工具升级；不以逼迫速度替代舒适清理。贝壳、海草、动物均不是垃圾。
- 锐物由手套与夹钳处理；不同地域现实垃圾分类制度不作为统一游戏答题规则。

## 完整内容与回放

3 张完整海滩，目标分别 24/30/36 件垃圾，共 6 种可辨识垃圾外观。后两图具有不同路线和阻挡关系，最后一图有 2 个卸货站，不能仅换颜色复制第一图。

分区恢复后小蟹、小鸟逐步回归，全部清理后展示前后对照明信片；清理少量残留时可启用提示，不强迫像素搜寻。生态回归不能阻塞拾取或成为可误收物品。

完成后可重玩，比较路程与卸货次数；提供受约束的布局变体，保证垃圾可达、大件数量与容量关系合理、关键路线不被不可解封死。不是无界随机散点。

## 存档与闭环

首次直接进入当前海滩；当前进度保存垃圾集合、车载货物、分区生态与地图标识，使用固定 `user://games/beach_cleanup/`。回岛再入继续；重玩明确确认后才重置本局，版本不兼容数据保留而非覆写。已卸货与车中垃圾不可因重载重复出现或计分。

完整循环：清理 → 选路线/卸货 → 恢复分区 → 明信片结算 → 下一海滩或重玩/回岛。没有收集装备、竞速硬门槛、联网或真实危险废物处理教学。模型/音频/UI/测试与来源记录独立放在本模块，入口与退出协议遵守宿主约定。

1. 12 格容量、1/3 格物品、连续扇形夹取、遮挡、不可收生态物、卸货与大件开路有明确测试。
2. 3 图全部可清完；后两图路线差异、末图双站、6 外观、分区回归和明信片在真实视口可见。
3. 中途满车回岛再入、应用重启、清理后恢复、重玩变体均不丢货/复制；残留提示确实指向剩余垃圾。
4. 人工完成全流程与真实抽离、存档隔离、宿主回归、源码推送核验后自动进入第六款。
